# Project brief

## Vision

Kairix PIMP — Production Ingest & Media Processor — is a practical desktop companion to Syncthing for the complete production-media lifecycle: verified camera offload, organization, catalogue search, project use, and eventually verified archive and safe cleanup. It is designed for editors who need footage to remain trustworthy while moving between computers and Adobe Premiere Pro projects.

PIMP does not replace Syncthing. A synchronized **Master Bin** holds original media and portable authoritative metadata. **Working Projects** hold active Premiere projects, project manifests, music, graphics, images, and other editing assets. Each computer maps these locations to its own absolute paths; synchronized references use stable identities and relative paths.

## Intended workflow

1. Connect camera storage and drag files or folders into PIMP.
2. Keep one of the exact persistent modes **Use today's date** or **Use original file dates**, then choose **Today**, **Yesterday**, **Choose date**, or **Use clip date** for each ingest.
3. Copy through temporary destinations, verify independent checksums, preserve source media, then catalogue successful copies.
4. Pair related video/audio only where filename, time, duration, and camera evidence are sufficient; keep pairing reversible.
5. Organize folders, apply folder-level and clip-level tags, and browse previews/contact sheets.
6. Combine search filters across names, dates, cameras, technical fields, tags, projects, review state, transcripts, and other metadata.
7. Assign a media item to zero, one, or many projects while preserving stable IDs.
8. Optionally run local Full-edition transcription, visual, and audio analysis. Store model provenance and uncertainty separately from manual metadata.
9. Import into Premiere through a documented UXP extension, retain dated bin structure, and reconcile the actual project state.
10. Track active projects through finalization. Inventory dependencies, produce a self-contained archive, verify independence and integrity, protect media used elsewhere, then offer explicitly authorized recoverable cleanup.

Windows is the first release target. Portable records and adapters are designed for future Linux and macOS implementations, which remain unverified.

## Editions

- **PIMP Light:** the complete non-AI workflow, including ingest, catalogue/search, project and Premiere workflows, archive workflows, and reading compatible AI metadata generated elsewhere. It must contain no unnecessary AI models or inference dependencies.
- **PIMP Full:** the same application, catalogue, and project formats plus optional local workers for transcription, timestamped search, scene/activity/object/sound analysis, and suggested tags.

AI processing is optional, local, modular, cancellable, and unable to block ordinary ingest or browsing.

## Current implementation — November 2026

Implemented now: the tested portable core and Node reference adapter plus a compiled Tauri host for device settings, restricted file and folder selection, native drops, explicit pre-copy source inventory, recursive verified ingest, authoritative per-device event streams, project manifests, conservative discovery, FFprobe metadata and FFmpeg thumbnails. Ingest retains common production media, camera sidecars and unknown package support files; it preserves camera-package and duplicate-name hierarchy, records source-relative provenance, and visibly accounts for deliberate exclusions and unreadable/traversal failures. Ingest runs through durable device-local jobs with stable IDs, bounded single-worker execution, per-file progress, between-file pause, cancellation and explicit retry. The real Library remains usable during transfer and supports folder browsing, combined search, accessible per-thumbnail checkboxes sharing desktop-style Ctrl/Shift/Ctrl+A selection, batch add/remove tags and projects, batch descriptions and favourites, and explicitly text-only multi-path clipboard copy. A navigable Projects workspace provides read-only categorized local-folder inventory, project notes/tags, linked logical recordings and validated Explorer navigation without interpreting `.prproj` contents.

Normal operation contains no synthetic catalogue entries. New devices show setup and empty-library guidance. Configured devices start reconciliation on launch, follow pending candidates after the conservative stability interval, and continue 30-second background scans. Quick and full verification controls report progress, pending files and errors; unchanged quick-scan files are not rehashed. Separate lightweight polling refreshes shared metadata and device-local availability without a discovery scan. Settings persistence completes before indexing; immediate preference writes are serialized, stale responses cannot roll back newer edits, and failures remain retryable. Frontend failures render a recovery view while recording a bounded device-local diagnostic log. Native ingest stages outside Master Bin; startup recovery marks unfinished work interrupted, independently verifies promoted bytes, reconciles completed registrations and preserves ambiguous journals for review. Provisional tags, projects, notes and favourites survive restart and retry and become authoritative only after verified registration. Byte-range transfer resume remains planned.

The Archive workspace now provides a provider-neutral external-drive backup foundation for complete registered Working Project folders. It preserves project-relative hierarchy, stages on the selected destination volume, promotes without overwrite, independently rereads every destination file against its planned SHA-256, persists interruption evidence, and supports recheck plus restore into a separate empty directory. This verifies copied project-folder bytes only; it does not prove Premiere dependency collection, archive independence, or cleanup eligibility, and it exposes no deletion operation.

Degoo remains an explicit official-browser handoff and is not a native backup provider. The disposable-account browser test required a manual Chrome upload and could not complete an independent download/hash comparison, so it is recorded as inconclusive and unverified. Review of the available reverse-engineered client found private web endpoints, browser impersonation, plaintext credential risks, no dependable remote digest and no verified current Windows lifecycle. No official public unattended API was identified. PIMP therefore stores no Degoo credentials or browser session, calls no private endpoint, and cannot mark a Degoo upload or listing as verified. A native adapter requires a documented supported interface or written provider authorization plus independent restored-byte SHA-256 verification.

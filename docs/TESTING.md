# Testing and verification

Never mark a check passed unless it was executed against the reported revision. Browser UI tests do not verify native Tauri behavior.

## Current repository commands

From `J:\projects\kairix-pimp`:

```powershell
npm install
npm test
npm run lint
npm run format
npm run build
npm audit --audit-level=high
```

`npm test` runs portable core, Node adapter, and jsdom React component/integration tests. `npm run build` type-checks project references and creates the production web bundle. CI repeats these checks on Ubuntu with Node 24 and FFmpeg. A separate `windows-latest` job runs native `cargo test` and `cargo check` with a cached stable Rust toolchain. The **Windows beta installer** workflow repeats TypeScript and Rust checks for pull requests, builds keyless unsigned MSI and NSIS bundles, and uploads short-lived version/commit artifacts. The protected **Publish public Windows beta** workflow repeats the full matrix from current `main` before creating a permanent manual prerelease. The separate protected **Publish signed automatic beta update** workflow verifies an existing release, signature and payload before replacing the fixed Beta channel manifest last.

The October 2026 milestone acceptance pass used disposable generated H.264/AAC MP4 and WAV media in the native packaged application. It verified folder selection, recursive ingest, independent checksums, FFprobe metadata, MP4/WAV pairing, thumbnail generation, tag and project assignment, and persistence after restart. It did not use personal media or substitute browser-only behavior for native validation.

The 2026-10-29 disposable Degoo Free-account exercise is not backup-verification evidence. The user reported a manual Chrome upload after the in-app picker failed, while the retained browser session could not complete an independent download because the desktop interface required Premium. No restored bytes were hashed. Record this outcome as **upload reported; remote verification blocked; not verified** and do not substitute it for provider-adapter, unattended-transfer or restore testing.

The 2026-10-30 reliability pass adds automated coverage for single-flight updater checks/installation, failed-check cleanup and retry, malformed/invalid-signature failures, interrupted-download invalidation, native update exclusion against active backup and critical filesystem permits, and unchanged full-verification evidence suppression. Rust tests also cover same-size content changes and clearing a prior mismatch after bytes return to the expected SHA-256. These are implementation tests, not evidence of a real installed signed upgrade.

## Test design rules

- Use synthetic or disposable fixtures; never personal footage.
- Keep destructive tests inside a uniquely created temporary fixture directory and verify its resolved boundary before cleanup.
- Assert outputs and failure state, not only that a call completed.
- Test interruption, replay, duplication, malformed inputs, and collision behavior for every persistent operation.
- Accessibility tests must exercise keyboard behavior and semantics. Manual assistive-technology checks remain necessary before release.
- FFmpeg-dependent tests may skip only with a visible reason. CI installs FFmpeg so those paths execute there.
- Record external application, OS, hardware, and version details for manual evidence.

The SD Grabber/global-deduplication suite uses synthetic card trees and Master Bin files. It covers recursive mixed-case MP4/WAV filtering, metadata exclusion, renamed/different-path SHA-256 matches, stale catalogue-only candidates, corrupted/missing local copies, same-size changed sources, active content reservations, source overlap, thumbnail-cache eviction and the Node adapter's concurrent destination race. UI coverage verifies the detected-card summary and copy-only action. These tests do not prove a particular physical card reader classification; installed Windows acceptance with disposable media remains required.

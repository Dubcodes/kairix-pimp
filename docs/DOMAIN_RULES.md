# Domain rules

These invariants are release gates. Each rule states observable behavior that tests or an explicit external verification procedure must establish.

| ID     | Invariant                                                                                                                                                                                                                                                                                                                         | Required evidence                                                                                                                                                                                          |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DR-001 | Original camera media remains unchanged.                                                                                                                                                                                                                                                                                          | Ingest tests compare source existence, size, timestamps where supported, and checksum before/after success, cancellation, and failure.                                                                     |
| DR-002 | A catalogue entry is created only after a complete independently checksum-verified copy.                                                                                                                                                                                                                                          | Corrupt/partial destination tests fail without registration; success rechecks the source and compares source/staging hashes.                                                                               |
| DR-003 | Existing files are never overwritten silently.                                                                                                                                                                                                                                                                                    | Identical content is reported as duplicate; atomic no-replace promotion preserves a destination created during copying.                                                                                    |
| DR-004 | Unsafe or ambiguous operations are reported rather than guessed.                                                                                                                                                                                                                                                                  | Unsupported dates/formats, path ambiguity, metadata conflict, and pairing uncertainty produce structured results or errors.                                                                                |
| DR-005 | All file operations remain within explicitly configured roots after canonical resolution.                                                                                                                                                                                                                                         | Traversal, symlink/junction escape, case, reserved-name, and out-of-root tests are rejected.                                                                                                               |
| DR-006 | Syncthing is the synchronization engine and its API is optional/read-only.                                                                                                                                                                                                                                                        | PIMP remains usable with no API; no code uploads or synchronizes files itself.                                                                                                                             |
| DR-007 | Shared authoritative metadata is safe for eventual synchronization.                                                                                                                                                                                                                                                               | Schema-2 replay tolerates ordering differences, clock skew and duplicates; causal set edits converge; scalar conflicts and damaged streams are retained/reported.                                          |
| DR-008 | A live SQLite database is never synchronized as authoritative data.                                                                                                                                                                                                                                                               | Repository formats and configuration place SQLite/FTS only in device-local, rebuildable state.                                                                                                             |
| DR-009 | Media can belong to multiple projects by stable project ID.                                                                                                                                                                                                                                                                       | Domain and UI tests preserve more than one project ID without replacing existing assignments.                                                                                                              |
| DR-010 | Folder tags and clip-specific tags remain distinguishable.                                                                                                                                                                                                                                                                        | Projection/search tests identify their source and do not rewrite inherited folder tags into clip metadata.                                                                                                 |
| DR-011 | Manual and AI-generated metadata remain separately identifiable.                                                                                                                                                                                                                                                                  | Serialized AI records include processor/version/provenance; manual edits never become AI records or vice versa.                                                                                            |
| DR-012 | Light and Full share compatible catalogue and project formats.                                                                                                                                                                                                                                                                    | The same schema fixtures load in both editions; Light's dependency/build inspection contains no inference runtime or model.                                                                                |
| DR-013 | Finalization verifies archive independence before cleanup eligibility.                                                                                                                                                                                                                                                            | External Premiere/archive tests prove all required dependencies resolve from the archive; failure blocks cleanup.                                                                                          |
| DR-014 | Shared source media remains protected while any non-finalized project requires it.                                                                                                                                                                                                                                                | Reference inventory tests keep the source ineligible when at least one active project manifest refers to its media ID.                                                                                     |
| DR-015 | Destructive cleanup requires explicit authorization and a recoverable quarantine.                                                                                                                                                                                                                                                 | Tests show no automatic source deletion; authorization, synchronization preflight, quarantine, and delayed purge are separate auditable steps.                                                             |
| DR-016 | Both ingest modes preserve ingest time plus original-date provenance and timezone when available.                                                                                                                                                                                                                                 | Tests cover one timestamp per Today/explicit-date batch and per-file timestamps for mixed original-date batches.                                                                                           |
| DR-017 | The per-ingest choices are exactly **Today**, **Yesterday**, **Choose date**, and **Use clip date**. They never replace the remembered **Use today's date** or **Use original file dates** mode. A date-only plan change revalidates source snapshots and destination safety without rehashing the card.                          | Native date-policy tests cover all four choices against both saved modes; UI tests cover initial selection, metadata-only reapproval and unchanged settings.                                               |
| DR-018 | Ordinary editing references footage directly from Master Bin; PIMP does not restructure Working Projects or automate Premiere path relinking.                                                                                                                                                                                     | Project workflow review confirms existing directories are preserved and manifests use relative Master Bin references.                                                                                      |
| DR-019 | Catalogue relocation after initialization is blocked until an explicit verified migration exists.                                                                                                                                                                                                                                 | Settings integration rejects a changed initialized location while the existing catalogue is present.                                                                                                       |
| DR-020 | Portable references do not depend on a device's absolute paths.                                                                                                                                                                                                                                                                   | Media/project/thumbnail references remain relative and remap to validated device-local roots.                                                                                                              |
| DR-021 | Creation in a searchable selector is explicit.                                                                                                                                                                                                                                                                                    | Typing an unknown value does not create data; only activating the visible create option can do so.                                                                                                         |
| DR-022 | Incomplete ingest data never enters the synchronized Master Bin.                                                                                                                                                                                                                                                                  | Staging is outside Master Bin; interruption recovery touches only journal-owned files; final promotion is no-overwrite.                                                                                    |
| DR-023 | External-copy discovery treats stability as evidence rather than proof.                                                                                                                                                                                                                                                           | Slow-copy tests require repeated observations over time; later changes reset stability and changed known files are revalidated.                                                                            |
| DR-024 | File-integrity evidence is device-specific and metadata edits never clear warnings.                                                                                                                                                                                                                                               | Per-device replay tests retain independent observations; only explicit matching SHA-256 verification clears the local warning.                                                                             |
| DR-025 | Date-folder formatting is device-local, validated before saving, and never renames existing folders.                                                                                                                                                                                                                              | Token tests cover compact, separated, 24-hour and 12-hour names plus path-separator/illegal-character rejection.                                                                                           |
| DR-026 | A project manifest with an incompatible identity is never overwritten.                                                                                                                                                                                                                                                            | Native tests preserve the original manifest bytes and return an actionable error.                                                                                                                          |
| DR-027 | Promoted-file recovery never trusts journal metadata alone.                                                                                                                                                                                                                                                                       | Native tests verify root, path, size, checksum and existing catalogue identity and preserve ambiguous journals and destinations.                                                                           |
| DR-028 | Open libraries notice shared metadata without requiring a media scan or Syncthing API.                                                                                                                                                                                                                                            | Native signature and UI polling tests cover tag-only and project-only event arrivals.                                                                                                                      |
| DR-029 | Incomplete ingest jobs keep metadata intent locally and never expose media as successfully ingested before verification.                                                                                                                                                                                                          | Job persistence/retry tests retain tags, projects, notes and favourite state; registration occurs only after verified promotion.                                                                           |
| DR-030 | Slow copying and hashing do not hold the catalogue write lock or block ordinary Library navigation.                                                                                                                                                                                                                               | Worker structure limits the lock to registration/event persistence; UI tests browse and edit queued-file metadata while a copy is active.                                                                  |
| DR-031 | Startup recovery never blindly resumes against removable media and never deletes a promoted destination.                                                                                                                                                                                                                          | Active states become interrupted for explicit retry; recovery tests independently verify promoted bytes and preserve ambiguous jobs.                                                                       |
| DR-032 | Media availability is device-local and may change without producing shared catalogue events.                                                                                                                                                                                                                                      | Availability polling tests observe an arriving known path without discovery, restart or event-stream mutation.                                                                                             |
| DR-033 | Re-ingesting an exact duplicate with no explicit metadata edits never clears existing metadata.                                                                                                                                                                                                                                   | Native duplicate tests retain identity, bytes, tags, two project assignments, notes and favourite state; explicit field clears remain separate events.                                                     |
| DR-034 | Startup marks a job file complete only after destination containment, ID, relative path, size and SHA-256 all agree.                                                                                                                                                                                                              | Native reconciliation tests cover valid promoted media, missing/partial destinations, hash/path/ID disagreement and conflicting registrations.                                                             |
| DR-035 | A completed-file metadata edit is not considered authoritative until its event append succeeds.                                                                                                                                                                                                                                   | Pending-write failure/restart tests preserve the local edit, retry idempotently and surface persistence errors.                                                                                            |
| DR-036 | File reveal, folder-open and path-copy actions never accept an arbitrary UI-supplied path.                                                                                                                                                                                                                                        | Native commands resolve a known media ID through the catalogue and canonical Master Bin containment before returning or launching anything.                                                                |
| DR-037 | Source inventory never silently drops a discovered file. Known temporary/application files are explicitly excluded; unknown camera-package files are retained, and unreadable or traversal failures prevent a completed status.                                                                                                   | Native inventory tests cover camera packages, sidecars, unknown files, duplicate basenames, partial-file exclusions and unavailable sources.                                                               |
| DR-038 | Batch metadata operations target only the explicit current selection, and manual Premiere handoff never claims undocumented project-file manipulation.                                                                                                                                                                            | UI tests cover Ctrl multi-selection, Ctrl+A, batch favourite updates, CRLF multi-path clipboard output and context-menu access.                                                                            |
| DR-039 | Device-local job history bounds only fully finalized work; failed, cancelled, interrupted, pending-metadata and recovery-evidence jobs are never automatically pruned.                                                                                                                                                            | Native tests retain more than 100 failed/cancelled jobs with provisional and pending metadata while bounding clean completed history to the newest 100 jobs.                                               |
| DR-040 | Separately selected source roots never collapse distinct same-relative-name files onto one planned destination.                                                                                                                                                                                                                   | Native tests cover standalone duplicate filenames and nested camera packages under two independent selected card roots.                                                                                    |
| DR-041 | Original-date organization never splits a detected camera package across date folders.                                                                                                                                                                                                                                            | Native tests assign MXF and XML package members with differing timestamps to the earliest available package-member date while independent files retain theirs.                                             |
| DR-042 | Background discovery never bypasses stability checks, blocks settings persistence, or rehashes unchanged verified files during a quick scan.                                                                                                                                                                                      | Discovery-state tests cover slow/change-reset files; UI integration covers startup scanning and independent settings completion; full scans are the explicit rehash path.                                  |
| DR-043 | Close-to-tray hides only when a usable tray exists, and support links never accept an arbitrary UI-supplied URL.                                                                                                                                                                                                                  | Native setup gates hiding on tray creation; Rust tests cover defaults and the support-link allowlist.                                                                                                      |
| DR-044 | Automatic updates are accepted only from the configured Beta manifest and only after Tauri signature verification; an unconfigured signing key fails closed.                                                                                                                                                                      | UI tests reject checks before updater access when signing is unconfigured; native tests reject tampered signed bytes; tagged CI alone may publish the protected manifest.                                  |
| DR-047 | Update installation and critical filesystem operations are mutually exclusive at the native host boundary; recoverable inactive jobs remain durable across an approved restart.                                                                                                                                                   | Rust gate tests cover ingest, active backup and operation permits for scan, verification, enrichment and preview work; updater tests cover rejection, retry and gate release after failure/success.        |
| DR-045 | Accepted device-preference edits are serialized and the response from an older write never replaces newer local edits.                                                                                                                                                                                                            | Queue and UI tests cover rapid tray, startup-page, update-check, theme and density changes, stale responses, restart persistence, visible failure and retry.                                               |
| DR-046 | Autostart may hide the main window only after a usable notification-area tray has been created.                                                                                                                                                                                                                                   | Native lifecycle policy tests cover minimized startup with and without an available tray.                                                                                                                  |
| DR-048 | An unambiguous same-directory, case-insensitive same-stem MP4/MOV and WAV pair is one logical Library recording; both physical files remain immutable.                                                                                                                                                                            | Native replay and grouped-Library tests cover ambiguity, late arrival, search, details and paired operations.                                                                                              |
| DR-049 | A normal Windows launch remains visible; autostart hides only with a working tray, and every restore route uses supported show/unminimize/focus behavior.                                                                                                                                                                         | Native policy tests plus installed-NSIS manual checks cover launch, second instance, tray click/menu and quit.                                                                                             |
| DR-050 | Release media tools do not create consoles, and Explorer selection still accepts only a known, available, root-contained media ID.                                                                                                                                                                                                | Windows CI checks the GUI PE subsystem; native tests cover child-process policy and special/offline known-media paths.                                                                                     |
| DR-051 | Offline registrations represent one logical recording only when normalized Master Bin relative path and SHA-256 both agree; replay aliases historic IDs without rewriting logs.                                                                                                                                                   | Rust and TypeScript permutation tests cover two/three devices, duplicate delivery, metadata preservation, legacy migration, same-hash/different-path separation and same-path/different-hash conflicts.    |
| DR-052 | Project directories are created or associated only beneath the canonically resolved Working Projects root.                                                                                                                                                                                                                        | Native path tests cover existing, missing, nested, traversal and symlink/junction escape cases before registration.                                                                                        |
| DR-053 | A committed catalogue edit is never rolled back or duplicated because its project-manifest projection failed.                                                                                                                                                                                                                     | Failure-injection tests persist pending reconciliation, preserve compatible unknown fields and retry after restart/drive recovery.                                                                         |
| DR-054 | A filename-derived external WAV attaches only when exactly one supported video and exactly one WAV share its case-insensitive directory and stem.                                                                                                                                                                                 | Native pairing tests cover MP4, MOV, MP4+MOV ambiguity, multiple WAVs, case differences, directories and late arrival.                                                                                     |
| DR-055 | Catalogue commits that require a project-manifest projection first persist device-local retry intent, and concurrent refresh, editing and project creation serialize only their manifest transaction.                                                                                                                             | Native tests cover concurrent refresh/update, failed intent and retry-state writes, repeated restart, post-registration path recovery, append failure and no-op refreshes.                                 |
| DR-056 | Library folder sorting and custom order are device-local presentation only and never rename, move or publish folder metadata.                                                                                                                                                                                                     | UI tests persist every sort mode and accessible custom-order movement while filesystem/catalogue operations remain absent.                                                                                 |
| DR-057 | A grouped video/WAV recording exposes metadata from both physical records and is counted once, while an explicitly shown WAV card targets only that WAV.                                                                                                                                                                          | Grouping and App tests cover WAV-only tags/projects/search, logical counts, paired bulk expansion and separate-WAV selection semantics.                                                                    |
| DR-058 | One authorized project directory has at most one project identity; retries reuse durable folder associations, and derived manifest media references follow safe canonical aliases without rewriting catalogue history.                                                                                                            | Native recovery tests cover pending/persisted paths, repeated creation, conflicting identities, restart and two-device stale-alias reconciliation with no-op repeat writes.                                |
| DR-059 | Project inventory and assignment changes never modify project assets or Master Bin originals; auto-saves are never selected as the main editing project.                                                                                                                                                                          | Synthetic `Simple Vlog 057` inventory and UI tests cover categorization, refresh, missing folders, logical assignments, path copying and removal without filesystem writes.                                |
| DR-060 | A superseded project scan never replaces the selected project's inventory or error state.                                                                                                                                                                                                                                         | Deferred UI requests complete and fail in reversed order; native inventory bounds excessive file counts/depth without following links, hashing, or writing project assets.                                 |
| DR-061 | Hover previews are regenerable device-local evidence and never modify or synchronize original media.                                                                                                                                                                                                                              | Fingerprint, frame-count, path-validation, cache-reuse/eviction and pointer-restoration tests cover local-only bounded generation.                                                                         |
| DR-062 | Thumbnail display never bypasses catalogue identity or device-local cache containment.                                                                                                                                                                                                                                            | Native batch resolution validates media IDs, expected filenames and canonical cache paths; 100/700/3,000-record UI tests assert one request per catalogue revision.                                        |
| DR-063 | Batch ingest tags add intent to eligible recordings without replacing later file-specific metadata or tagging support files.                                                                                                                                                                                                      | Native normalization/eligibility tests and UI request tests cover video/audio/image seeding, sidecar exclusion and merged later tags.                                                                      |
| DR-064 | Source cleanup is never implied by verified copy completion and never runs in Copy mode. It requires whole-batch and package completeness, canonical non-overlap, unchanged source identity and bytes, committed destination SHA-256, an exact review, separate confirmation and a durable per-file cleanup journal.              | `SOURCE_CLEANUP_DESIGN.md` defines the disabled safety gate; no destructive command or UI control exists.                                                                                                  |
| DR-065 | An unconfigured updater must be reported as unavailable before any network check; manual test-build and Releases links never imply a signed release exists.                                                                                                                                                                       | UI tests assert no checker call without configuration, distinct configured states, and native tests enforce the fixed destination allowlist.                                                               |
| DR-066 | Clearing completed ingest history may remove only a device-local job record that is fully finalized and has no inventory issue, file error, unresolved failure, pending metadata or recovery journal. It never removes media, events, staging data or sources.                                                                    | Native tests cover individual/all/repeated clearing, active and recoverable states, restart persistence and completion races; UI tests cover separate counts and collapsed history.                        |
| DR-067 | Hover-preview memory and disk clearing are bounded and generation-aware. Concurrent identical requests deduplicate, stale epochs cannot render, and cache directories are removed only while holding the preview-generation mutex.                                                                                                | Request-cache tests cover LRU and in-flight bounds; native tests prove clear waits for generation and stays within the device-local cache.                                                                 |
| DR-068 | A mounted Library card may retain one bounded preview while it is near the viewport to display its selected hold frame, but releases it after leaving the active viewport; unchanged disk-cached frames remain reusable.                                                                                                          | UI tests cover hold restoration; observer handling and the shared request cache bound retained frame collections.                                                                                          |
| DR-069 | Hover-preview timecodes describe the frames FFmpeg actually emitted, including irregular cadence and non-zero timestamps, rather than assumed evenly spaced positions.                                                                                                                                                            | Native parsing tests cover short, long, decimal and non-zero `showinfo` timestamps; cache schema/fingerprint versioning invalidates older assumed-time manifests.                                          |
| DR-070 | Thumbnail hold choices select the nearest actual cached sample and never synthesize false timecodes; last-hover position is bounded device-local presentation state, not synchronized catalogue metadata.                                                                                                                         | Component tests cover irregular sample selection and per-media local persistence; missing previews retain the ordinary thumbnail.                                                                          |
| DR-071 | Preview preparation is bounded, device-local and lower priority than an explicit hover or active verified ingest. Optional offscreen preparation waits for browser idle and defers again on interaction. Disk generation does not transfer Base64 frames; RAM retention is governed by approximate bytes, not a fixed clip count. | Queue and idle-gate tests cover priority, deduplication, interaction deferral and saturation; cache tests cover byte eviction; native preparation defers while ingest is active.                           |
| DR-072 | Premiere handoff exports only an explicit physical selection resolved beneath canonical Master Bin, includes selected attached audio, refuses manifest overwrite and never modifies media or `.prproj` files.                                                                                                                     | Native manifest tests cover canonical local availability and audio linkage; plugin validator tests cover schema, paths, hashes and duplicates.                                                             |
| DR-073 | A project backup is verified only after same-volume staging, source-consistency checks, atomic no-overwrite promotion and an independent full destination SHA-256 pass. Backup evidence never authorizes cleanup.                                                                                                                 | Native synthetic tests cover hierarchy/Unicode preservation, collisions, tampering, overlap rejection and a full independent restore; the UI exposes no cleanup action.                                    |
| DR-074 | A remote backup remains verification-pending until PIMP independently reads every stored object through a supported provider interface and matches the immutable manifest. Upload acknowledgement, listings, metadata and manual browser transfer are insufficient.                                                               | Provider-adapter tests must cover independent restored-byte SHA-256, missing/truncated/tampered objects, expired authorization, retry and interruption; no provider currently satisfies this release gate. |
| DR-075 | Re-verifying unchanged local integrity evidence never appends a redundant synchronized event; changed bytes and recovery from a mismatch remain authoritative observations.                                                                                                                                                       | Native tests cover identical full-verification evidence, same-size changed bytes, recovery to the expected SHA-256 and equality recheck against the latest projection.                                     |
| DR-076 | Ingest starts only from a persisted approved inventory. It revalidates every exact source and never includes files that arrived after review.                                                                                                                                                                                     | Native approved-source tests cover same-size changed bytes; job plans retain source snapshot/hash and destination mapping through retry.                                                                   |
| DR-077 | A global duplicate skip requires matching SHA-256 plus a fresh, stable local read beneath Master Bin. Catalogue-only, unavailable, changing or corrupt candidates are not trusted.                                                                                                                                                | Native tests cover renamed/different-date content, corruption, unavailability, same-size different content and metadata preservation.                                                                      |
| DR-078 | SD Card Grabber selects only configured extensions (MP4/WAV by default), preserves nested relative paths, and uses verified ingest. It never deletes or modifies card content.                                                                                                                                                    | Native filter tests cover mixed-case nested media and excluded metadata; UI tests cover detected-card review and copy-only wording.                                                                        |
| DR-079 | Selected sources may not overlap Master Bin, native staging or application working data after canonical resolution.                                                                                                                                                                                                               | Native tests cover bidirectional overlap; existing filesystem tests cover traversal and link/junction escape.                                                                                              |
| DR-080 | Device-local hover-preview and playback-proxy eviction is byte-bounded and never traverses shared static thumbnails or user media.                                                                                                                                                                                                | Native eviction tests operate only within validated device-local cache roots; shared static cleanup requires a separate reviewed operation.                                                                |
| DR-081 | Source inventory traversal, hashing and duplicate inspection never run on the desktop event thread. One serialized worker reports bounded progress and cooperatively cancels superseded work.                                                                                                                                     | Native cancellation tests stop a multi-chunk read and stale-operation tests prove the newer request cancels the prior operation; UI tests expose progress and cancellation.                                |
| DR-082 | Promotion requires the exact bytes copied from the source to match the reviewed SHA-256, and removable-volume identity remains stable through the transfer when the platform provides it.                                                                                                                                         | Native copy tests reject same-size changed content before promotion; inventory/job schema defaults preserve older stores.                                                                                  |
| DR-083 | A conflicting destination filename requires explicit rename review and a newly persisted approved plan; an existing destination is never replaced.                                                                                                                                                                                | Native planning and UI contract tests cover conflict evidence, safe leaf filenames and no-overwrite paths.                                                                                                 |
| DR-084 | Missing or corrupt catalogue copies are never silently trusted as duplicates. A new physical copy requires explicit user intent and still follows normal source validation, staging verification and no-overwrite promotion.                                                                                                      | Native request tests preserve source-change rejection and UI tests pass the opt-in only when selected.                                                                                                     |
| DR-085 | Library checkbox, card, Ctrl/Shift and Ctrl+A interactions update one logical selection; grouped attached audio expands only when resolving physical operations.                                                                                                                                                                  | UI tests cover mouse and keyboard checkbox toggle/deselection without collapsing another selected recording; existing grouping tests cover attached WAV expansion.                                         |
| DR-086 | Clipboard path copy is text only and is never represented as a Premiere import. Human/API paths remove an extended drive prefix only when the ordinary path is short and legacy-safe; verification paths remain canonical and unchanged.                                                                                          | Native and companion tests cover spaces, Unicode, drive paths, UNC, extended UNC, genuinely long paths and trailing-dot paths.                                                                             |
| DR-087 | Explorer reveal changes path representation only at the Windows Shell boundary and supplies a parent folder plus child item; canonical safety paths remain unchanged.                                                                                                                                                             | Native boundary tests cover drive, UNC, extended, Unicode, comma, long and legacy-unsafe paths; installed selection acceptance remains required.                                                           |
| DR-088 | A thumbnail reference is not proof that valid derivative bytes are locally available. Missing, empty or invalid shared thumbnails remain retryable and are committed only from a validated uniquely named temporary file with no-overwrite promotion.                                                                             | Native validity/migration tests and UI image-error tests cover regeneration eligibility and placeholder fallback without touching media.                                                                   |
| DR-089 | Description drafts and save status are keyed to the exact logical selection. Late or failed saves never replace another selection's editor, and unchanged descriptions emit no new authoritative event.                                                                                                                           | UI tests cover selection changes, late completion and failed draft retention; native update construction suppresses unchanged notes/favourite events.                                                      |
| DR-090 | Clip playback and custom thumbnail generation resolve a known media ID beneath Master Bin. They never modify, rename or transcode the original in place.                                                                                                                                                                          | UI tests cover viewer navigation/errors; native tests cover bounded frame time, stable source evidence and cache-only output.                                                                              |
| DR-091 | Unavailable means absent on this device, not archived or cleanup-safe. Local recordings are the default Library projection and historical records require an explicit inclusion control.                                                                                                                                          | UI filtering tests distinguish local availability from archive state and preserve the catalogue record.                                                                                                    |
| DR-092 | Saved Premiere indexing reads one bounded stable snapshot, never writes project files, rejects unsafe XML constructs and keeps its projection device-local. It exposes only canonical named definitions and unambiguous reference relationships; unknown time ranges or usage are never fabricated.                               | Sanitized fixtures cover definitions/references, root/nested bins, imported/used/unclassified evidence, placements, unsafe input and unchanged source bytes.                                               |
| DR-093 | Project-media association requires exact existing canonical-path evidence. Filename equality is insufficient, and unknown/partial parsing never becomes Not imported or cleanup eligibility.                                                                                                                                      | Parser/UI tests retain unresolved references and explicit partial/unsupported status without negative claims.                                                                                              |
| DR-094 | Changing only an ingest date preserves the exact approved source list, hashes, snapshots and package hierarchy. It never walks source roots or reads source content, and a superseded plan revision cannot start ingest.                                                                                                          | Native tests cover package and independent-file date mapping plus immutable lineage revisions; UI tests serialize rapid choices and rebase the latest intent on the durable revision.                      |
| DR-095 | A playback proxy is cache-only and valid only after its encoder exits, FFprobe proves the expected finalized codecs/container and duration, and the source snapshot remains unchanged. Cancellation waits for process termination before deleting partial output.                                                                 | Native tests cover probe semantics, progress parsing, budget/protected-partial cleanup and source-stability helpers; UI tests cover time progress and cancellation routing.                                |
| DR-096 | Editable controls, searchable combos, menus and modal interactions own their keystrokes. Global media/selection shortcuts never replace native typing, text selection or undo/redo.                                                                                                                                               | UI tests preserve typed shortcut characters and native Ctrl+Z, then prove playback resumes after focus leaves the editor.                                                                                  |
| DR-097 | Saved-project indexing never infers “unused” or historical use from an arbitrary path. Historical evidence requires a prior positive observation for the same path, and incomplete timeline coverage remains unknown rather than zero.                                                                                            | Native tests distinguish positive history from unclassified evidence; UI tests expose Unknown and both evidence labels.                                                                                    |
| DR-098 | Static thumbnails and hover previews have independent bounded work paths. Hover generation or clearing cannot cancel or starve visible static work. A disk manifest is only stored evidence; preview-ready UI requires scrub frames to be loaded and usable now.                                                                  | Queue tests block generation while a cached load completes; component tests cover stored-versus-loaded readiness and clearing; native validation rejects stale or incomplete preview entries.              |

| DR-099 | Background progress comes from native worker state. One measured primary operation may drive title/taskbar progress; unrelated jobs are never combined into a fabricated percentage, and high-frequency progress is never synchronized metadata. | Native transient-operation tests cover queued/running lifetime; UI tests retain real determinate/indeterminate operation presentation. | DR-100 | Library thumbnail size is a bounded device preference that changes responsive layout only. | DR-101 | Derivative FFmpeg work is globally serialized and priority-aware. | DR-102 | A Windows outbound drag contains only canonical, locally available selected files or one real folder beneath the Master Bin, is bounded, rechecks recorded identity and offers COPY only. It never expands a logical recording to attached audio, represents a virtual collection as a folder or authorizes source mutation. | Native tests cover bounds, stale identity, Unicode/spaces, root escape and physical folders; UI tests cover explicit multi-selection and folder payloads. | DR-103 | Hover generation decodes only bounded targeted samples, records actual FFmpeg timestamps, has one finite wall-clock deadline and publishes no partial entry. Derivative byte diagnostics never count the source's logical file length as measured FFmpeg reads. | Native tests cover sample bounds, endpoint clamping, timestamp parsing, cache schema validation, unpublished-directory cleanup and synchronized cache clearing. | DR-102 | Full-content work acquires device-local volume permits by stable volume identity rather than drive letter. | DR-103 | Quick Library inventory reads filesystem metadata only. | DR-104 | Shared static thumbnails are regenerable, content/transform-identified files beneath the shared catalogue. | DR-105 | A valid static thumbnail source remains retained across card unmount, filtering and ordinary catalogue refresh. | DR-106 | Library scroll ownership belongs only to its folder and media panels. Other pages use the main viewport scrollbar only when content overflows. | Component tests assert view-specific main classes; CSS uses a fixed-height shell, flex/grid `min-height: 0`, hidden Library parent overflow and independent panel overflow. |
| DR-107 | Stable/Development is explicit release metadata. Numeric version components are compared as integers; whole-major Stable versions require protected approval, and unsigned/unclassified or wrong-channel updates fail closed. | Release-policy and updater tests cover `1.22 > 1.3`, legacy parsing, classification/channel rejection and missing signing configuration. |

When a proposed feature cannot preserve a rule, stop and record the conflict in [DECISIONS.md](DECISIONS.md) before implementation. Safety rules are not weakened by calling work experimental.

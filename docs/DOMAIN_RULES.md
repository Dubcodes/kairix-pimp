# Domain rules

These invariants are release gates. Each rule states observable behavior that tests or an explicit external verification procedure must establish.

| ID     | Invariant                                                                                                                                                                                                                       | Required evidence                                                                                                                                                         |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DR-001 | Original camera media remains unchanged.                                                                                                                                                                                        | Ingest tests compare source existence, size, timestamps where supported, and checksum before/after success, cancellation, and failure.                                    |
| DR-002 | A catalogue entry is created only after a complete independently checksum-verified copy.                                                                                                                                        | Corrupt/partial destination tests fail without registration; success rechecks the source and compares source/staging hashes.                                              |
| DR-003 | Existing files are never overwritten silently.                                                                                                                                                                                  | Identical content is reported as duplicate; atomic no-replace promotion preserves a destination created during copying.                                                   |
| DR-004 | Unsafe or ambiguous operations are reported rather than guessed.                                                                                                                                                                | Unsupported dates/formats, path ambiguity, metadata conflict, and pairing uncertainty produce structured results or errors.                                               |
| DR-005 | All file operations remain within explicitly configured roots after canonical resolution.                                                                                                                                       | Traversal, symlink/junction escape, case, reserved-name, and out-of-root tests are rejected.                                                                              |
| DR-006 | Syncthing is the synchronization engine and its API is optional/read-only.                                                                                                                                                      | PIMP remains usable with no API; no code uploads or synchronizes files itself.                                                                                            |
| DR-007 | Shared authoritative metadata is safe for eventual synchronization.                                                                                                                                                             | Schema-2 replay tolerates ordering differences, clock skew and duplicates; causal set edits converge; scalar conflicts and damaged streams are retained/reported.         |
| DR-008 | A live SQLite database is never synchronized as authoritative data.                                                                                                                                                             | Repository formats and configuration place SQLite/FTS only in device-local, rebuildable state.                                                                            |
| DR-009 | Media can belong to multiple projects by stable project ID.                                                                                                                                                                     | Domain and UI tests preserve more than one project ID without replacing existing assignments.                                                                             |
| DR-010 | Folder tags and clip-specific tags remain distinguishable.                                                                                                                                                                      | Projection/search tests identify their source and do not rewrite inherited folder tags into clip metadata.                                                                |
| DR-011 | Manual and AI-generated metadata remain separately identifiable.                                                                                                                                                                | Serialized AI records include processor/version/provenance; manual edits never become AI records or vice versa.                                                           |
| DR-012 | Light and Full share compatible catalogue and project formats.                                                                                                                                                                  | The same schema fixtures load in both editions; Light's dependency/build inspection contains no inference runtime or model.                                               |
| DR-013 | Finalization verifies archive independence before cleanup eligibility.                                                                                                                                                          | External Premiere/archive tests prove all required dependencies resolve from the archive; failure blocks cleanup.                                                         |
| DR-014 | Shared source media remains protected while any non-finalized project requires it.                                                                                                                                              | Reference inventory tests keep the source ineligible when at least one active project manifest refers to its media ID.                                                    |
| DR-015 | Destructive cleanup requires explicit authorization and a recoverable quarantine.                                                                                                                                               | Tests show no automatic source deletion; authorization, synchronization preflight, quarantine, and delayed purge are separate auditable steps.                            |
| DR-016 | Both ingest modes preserve ingest time plus original-date provenance and timezone when available.                                                                                                                               | Tests cover one timestamp per Today/explicit-date batch and per-file timestamps for mixed original-date batches.                                                          |
| DR-017 | A per-ingest Today, Yesterday, or chosen-date override never replaces the remembered organization mode.                                                                                                                         | Native contract and UI tests cover request-only overrides and shared-setting persistence.                                                                                 |
| DR-018 | Ordinary editing references footage directly from Master Bin; PIMP does not restructure Working Projects or automate Premiere path relinking.                                                                                   | Project workflow review confirms existing directories are preserved and manifests use relative Master Bin references.                                                     |
| DR-019 | Catalogue relocation after initialization is blocked until an explicit verified migration exists.                                                                                                                               | Settings integration rejects a changed initialized location while the existing catalogue is present.                                                                      |
| DR-020 | Portable references do not depend on a device's absolute paths.                                                                                                                                                                 | Media/project/thumbnail references remain relative and remap to validated device-local roots.                                                                             |
| DR-021 | Creation in a searchable selector is explicit.                                                                                                                                                                                  | Typing an unknown value does not create data; only activating the visible create option can do so.                                                                        |
| DR-022 | Incomplete ingest data never enters the synchronized Master Bin.                                                                                                                                                                | Staging is outside Master Bin; interruption recovery touches only journal-owned files; final promotion is no-overwrite.                                                   |
| DR-023 | External-copy discovery treats stability as evidence rather than proof.                                                                                                                                                         | Slow-copy tests require repeated observations over time; later changes reset stability and changed known files are revalidated.                                           |
| DR-024 | File-integrity evidence is device-specific and metadata edits never clear warnings.                                                                                                                                             | Per-device replay tests retain independent observations; only explicit matching SHA-256 verification clears the local warning.                                            |
| DR-025 | Date-folder formatting is device-local, validated before saving, and never renames existing folders.                                                                                                                            | Token tests cover compact, separated, 24-hour and 12-hour names plus path-separator/illegal-character rejection.                                                          |
| DR-026 | A project manifest with an incompatible identity is never overwritten.                                                                                                                                                          | Native tests preserve the original manifest bytes and return an actionable error.                                                                                         |
| DR-027 | Promoted-file recovery never trusts journal metadata alone.                                                                                                                                                                     | Native tests verify root, path, size, checksum and existing catalogue identity and preserve ambiguous journals and destinations.                                          |
| DR-028 | Open libraries notice shared metadata without requiring a media scan or Syncthing API.                                                                                                                                          | Native signature and UI polling tests cover tag-only and project-only event arrivals.                                                                                     |
| DR-029 | Incomplete ingest jobs keep metadata intent locally and never expose media as successfully ingested before verification.                                                                                                        | Job persistence/retry tests retain tags, projects, notes and favourite state; registration occurs only after verified promotion.                                          |
| DR-030 | Slow copying and hashing do not hold the catalogue write lock or block ordinary Library navigation.                                                                                                                             | Worker structure limits the lock to registration/event persistence; UI tests browse and edit queued-file metadata while a copy is active.                                 |
| DR-031 | Startup recovery never blindly resumes against removable media and never deletes a promoted destination.                                                                                                                        | Active states become interrupted for explicit retry; recovery tests independently verify promoted bytes and preserve ambiguous jobs.                                      |
| DR-032 | Media availability is device-local and may change without producing shared catalogue events.                                                                                                                                    | Availability polling tests observe an arriving known path without discovery, restart or event-stream mutation.                                                            |
| DR-033 | Re-ingesting an exact duplicate with no explicit metadata edits never clears existing metadata.                                                                                                                                 | Native duplicate tests retain identity, bytes, tags, two project assignments, notes and favourite state; explicit field clears remain separate events.                    |
| DR-034 | Startup marks a job file complete only after destination containment, ID, relative path, size and SHA-256 all agree.                                                                                                            | Native reconciliation tests cover valid promoted media, missing/partial destinations, hash/path/ID disagreement and conflicting registrations.                            |
| DR-035 | A completed-file metadata edit is not considered authoritative until its event append succeeds.                                                                                                                                 | Pending-write failure/restart tests preserve the local edit, retry idempotently and surface persistence errors.                                                           |
| DR-036 | File reveal, folder-open and path-copy actions never accept an arbitrary UI-supplied path.                                                                                                                                      | Native commands resolve a known media ID through the catalogue and canonical Master Bin containment before returning or launching anything.                               |
| DR-037 | Source inventory never silently drops a discovered file. Known temporary/application files are explicitly excluded; unknown camera-package files are retained, and unreadable or traversal failures prevent a completed status. | Native inventory tests cover camera packages, sidecars, unknown files, duplicate basenames, partial-file exclusions and unavailable sources.                              |
| DR-038 | Batch metadata operations target only the explicit current selection, and manual Premiere handoff never claims undocumented project-file manipulation.                                                                          | UI tests cover Ctrl multi-selection, Ctrl+A, batch favourite updates, CRLF multi-path clipboard output and context-menu access.                                           |
| DR-039 | Device-local job history bounds only fully finalized work; failed, cancelled, interrupted, pending-metadata and recovery-evidence jobs are never automatically pruned.                                                          | Native tests retain more than 100 failed/cancelled jobs with provisional and pending metadata while bounding clean completed history to the newest 100 jobs.              |
| DR-040 | Separately selected source roots never collapse distinct same-relative-name files onto one planned destination.                                                                                                                 | Native tests cover standalone duplicate filenames and nested camera packages under two independent selected card roots.                                                   |
| DR-041 | Original-date organization never splits a detected camera package across date folders.                                                                                                                                          | Native tests assign MXF and XML package members with differing timestamps to the earliest available package-member date while independent files retain theirs.            |
| DR-042 | Background discovery never bypasses stability checks, blocks settings persistence, or rehashes unchanged verified files during a quick scan.                                                                                    | Discovery-state tests cover slow/change-reset files; UI integration covers startup scanning and independent settings completion; full scans are the explicit rehash path. |
| DR-043 | Close-to-tray hides only when a usable tray exists, and support links never accept an arbitrary UI-supplied URL.                                                                                                                | Native setup gates hiding on tray creation; Rust tests cover defaults and the support-link allowlist.                                                                     |
| DR-044 | Automatic updates are accepted only from the configured Beta manifest and only after Tauri signature verification; an unconfigured signing key fails closed.                                                                    | UI tests reject checks before updater access when signing is unconfigured; native tests reject tampered signed bytes; tagged CI alone may publish the protected manifest. |
| DR-045 | Accepted device-preference edits are serialized and the response from an older write never replaces newer local edits.                                                                                                          | Queue and UI tests cover rapid tray, startup-page, update-check, theme and density changes, stale responses, restart persistence, visible failure and retry.              |
| DR-046 | Autostart may hide the main window only after a usable notification-area tray has been created.                                                                                                                                 | Native lifecycle policy tests cover minimized startup with and without an available tray.                                                                                 |

When a proposed feature cannot preserve a rule, stop and record the conflict in [DECISIONS.md](DECISIONS.md) before implementation. Safety rules are not weakened by calling work experimental.
